## Failures And Attribution

### Map ABI drift

Sixteen invalid-state stops came from
`NMapDrawings.GetLocalDrawingMode()`. In v0.110.0 the CLR signature changed to
`GetLocalDrawingMode(bool useOverride = true)`. A DLL compiled against the old
zero-parameter method threw `MissingMethodException`; an optional source
parameter does not preserve the old CLR call signature.

The repaired source binds only the audited zero-parameter or one-boolean
signature and invokes the current form with `true`. It also moves map travel
and annotation controls to V3 direct native resolvers. This repair has source
and automated evidence only until a new artifact is cold-loaded.

### Dream Catcher rest completion

`run-20260731034655-c22gu4` submitted Heal at a rest site. Native healing
occurred, then Dream Catcher opened an exact card-reward child. The old Outcome
waited for parent progress and timed out, producing the only
`unknown/unknown` receipt.

The repaired Outcome accepts the exact minimum HP increase plus the exact
native `NCardRewardSelectionScreen` child handoff as action-local completion.
Rest controls now use V3 direct native resolvers. This repair is pending a new
exact-runtime action.

### Symbiote deck enchant source

`run-20260731035127-qn4mc8` reached the Symbiote event's Corrupted enchant
selector. The loaded Gateway correctly exposed a visible unsupported
interaction because the source was not yet registered. Re then incorrectly
projected that reduced unsupported payload as a full v2 deck-enchant surface
and failed strict decode on the absent `stage`.

Re now projects every V3 `execution_support=unsupported` interaction as a
typed unsupported surface. The Gateway separately adds an exact Symbiote
source contract: exact event task, Corrupted enchantment, one required card,
non-cancelable automatic commit, exact screen/card operands, and V3 direct
native resolvers. The repair does not generalize unknown enchant callers and
is pending exact-runtime mutation evidence.
